## 이 프로젝트가 실제로 푸는 문제

주식 정보 도구를 만들 때 가장 무서운 실패는 **틀린 값이 나오는 것이 아니라,
낡은 값이 최신인 척 통과하는 것**입니다. 오류는 눈에 띄지만, 조용한 통과는
안 띄기 때문입니다.

이 저장소의 커밋 절반은 그 "조용한 실패"를 하나씩 찾아 막은 기록입니다.

| 실제로 있었던 일 | 무엇이 문제였나 |
|---|---|
| 공매도 데이터가 **5일 전 값**인 채로 근거에 쓰임 | 수집기가 실패해도 어제 파일이 그 자리에 남아 그대로 통과 |
| 추석 당일을 **'평일'로 판정** | 휴장일 목록을 과거 데이터에서 역산해 만들어, 구조상 미래를 못 담음 |
| 뉴스 수집기 5종이 **한 달 넘게 안 돌고 있었음** | 코드는 멀쩡한데 호출부가 지시문에만 있었음 |
| 자료 조회 도구가 **한 번도 안 돌았음** | 권한 규칙 문법이 한 글자 틀렸는데, '승인 필요'가 오류로 안 보여서 아무도 몰랐음 |

그래서 이 시스템의 판정 규칙은 이렇습니다.

- **"파일이 있다"는 성공이 아니다** — ①이번 실행으로 갱신됐는가 ②안의 날짜가 전 거래일인가, 둘 다 봐야 통과
- **"확인 불가"와 "0"은 다르다** — 실패는 `ok:false`와 사유로 남기고, 절대 0으로 채우지 않음
- **오늘 봉으로 정산하지 않는다** — 장중에 예측을 채점하면 미래를 훔쳐본 것이 됨

## 회고 폐루프 — 이 프로젝트의 핵심

```
아침 예측  →  predictions.json
                   ↓  (만기 도래)
             자동 채점  →  accuracy_log.json (append-only 원장)
                   ↓
             회고 분석  →  "어떤 규칙이 틀렸나"
                   ↓
             retro_feedback.md  →  다음 날 아침 지시서에 반영
```

**과적합을 막는 장치를 함께 넣었습니다.** 규칙을 계속 추가하면 과거에는 잘 맞고
미래에는 안 맞는 시스템이 되기 때문입니다.

- **사전 등록** — 규칙을 먼저 적고, 그 다음에 성적을 봅니다(결과를 보고 규칙을 만들지 않음)
- **다중비교 보정** — 규칙을 30개 시험하면 그중 1~2개는 우연히 맞습니다. Bonferroni·BH-FDR 로 걸러냅니다
- **3단 신뢰도** — 검증 / 관찰 / 가설로 나눠, 근거가 약한 규칙은 약하다고 표시합니다
- **규칙 상한 30개 + 가지치기 의무** — 늘리기만 하고 줄이지 않으면 반드시 과적합됩니다

## 구조

```
수집 (21단계)          분석                발송·공개           회고
─────────────────    ──────────────    ──────────────    ──────────────
뉴스 5종               Claude 기반        메일 (Apps Script)  자동 채점
수급·외국인/기관        지시서 규율        웹사이트 (Flask)     규칙 성적표
공시 (DART)           호재/악재 판정      HTS 캡처 첨부       가지치기
파생·신용잔고          예측 발행                              다음날 반영
HTS 화면 캡처
```

- `run_signals.py` — 21단계 수집을 한 줄로. 단계별 신선도를 `OK / STALE / EMPTY / FAIL` 로 판정
- `retro_label.py`, `accuracy_tracker.py` — 채점과 원장
- `tests/run_tests.py` — 순수함수·계약 559개 검증
- `setup_kit/` — 처음부터 세우는 데 필요한 것 전부 (아래)
- `CODEMAP.md` — 파일별 역할·입출력 지도

## 직접 돌려보려면

**`setup_kit/00_먼저_읽어주세요.md` 부터 보세요.** 설치 순서, 필요한 API 키,
Apps Script 배포, 예정작업 등록이 단계별로 적혀 있습니다.

API 키 파일의 양식은 `examples/` 에 있습니다 — 복사해서 `.example` 를 떼고
값을 채우면 됩니다. 실제 키가 담긴 파일은 저장소에 올라가지 않습니다.

```bash
python tests/run_tests.py        # 설치 없이도 도는 검증 (약 5초)
python run_signals.py --check    # 무엇을 언제 수집했는지 점검
```

## 무엇이 저장소에 없는가

개인정보와 자격증명은 빠져 있습니다. 일부러 뺐습니다.

- API 키 (`*_api.txt`) — `examples/` 에 **값이 빈 양식**만
- 수신자 이메일 (`mail_config.txt`) — 양식만
- 회원별 보유 종목·손익 — 타인의 개인정보라 어떤 형태로도 없음
- 매일 만들어지는 산출물 (`output/`) — 리포트·캡처·예측 기록

커밋할 때마다 `tools/check_no_secrets.py` 가 **스테이징된 내용 자체**를 검사해
이메일·키·계좌번호 형태가 섞이면 커밋을 막습니다.
