# 포트폴리오 등록 웹앱 설치 (Apps Script) — v11.13

친구들이 **각자 자기 포트폴리오를 직접 등록**하면, 매일 아침 **각자에게만** 보유 현황과
전략 메일이 가는 구조다. 사람 구분은 **이메일 주소**로 한다.

```
친구 → 웹 폼(이메일 확인 코드) → Google Sheet
                                    ↓ portfolio_sync.py (SECRET 필요)
                        portfolios/<이메일>.csv
                                    ↓ portfolio_review.py --all
                        아침 리서치가 사람별 전략 작성
                                    ↓ portfolio_mail.py --all --send
                        각자에게 자기 것만 발송
```

---

## 1. 웹앱 만들기 (10분, 한 번만)

★**파일이 2개다.** 코드와 화면을 나눠 뒀다 — 둘 다 넣어야 동작한다.

1. <https://script.google.com> → **새 프로젝트**
2. `Code.gs` 내용을 지우고 **`cowork/portfolio_webapp.gs` 전체를 붙여넣기**
3. 왼쪽 **파일 옆 `+` → HTML** → 이름을 정확히 **`index`** 로 짓고
   (`.html` 은 자동으로 붙는다) **`cowork/portfolio_webapp_index.html` 전체를 붙여넣기**
   - 기본으로 들어 있는 내용은 지우고 넣어라.
   - 이름이 `index` 가 아니면 첫 화면에서 바로 에러가 난다(`doGet` 이 이 이름으로 찾는다).
4. 맨 위 `var SECRET = '...'` 이 **길고 무작위한 값**인지 확인한다(이미 채워져 있으면 그대로 둔다).
   새로 만들려면 pc21 에서:
   ```bash
   python -c "import secrets; print(secrets.token_urlsafe(32))"
   ```
   바꿨으면 **`portfolio_sync_config.txt` 의 `secret=` 도 같은 값으로** 맞춰야 한다.
5. 저장 → **배포 → 새 배포 → 유형 '웹 앱'**
   - 설명: `포트폴리오 등록`
   - **실행: 나(본인 계정)**  ← 확인 코드 메일이 내 계정에서 나간다
   - **액세스 권한: 모든 사용자**  ← 친구들이 로그인 없이 쓸 수 있게
6. 권한 승인 화면이 뜬다 → "고급" → "안전하지 않은 페이지로 이동" → 허용
   (내가 만든 스크립트라 정상이다. 시트 읽기·쓰기와 메일 발송 권한을 요구한다)
7. 나오는 **웹 앱 URL**(`.../exec` 로 끝남)을 복사해 둔다.

★코드를 고칠 때마다 **배포 → 배포 관리 → 연필(수정) → 버전 '새 버전' → 배포**를 해야
  반영된다. 저장만 하면 배포본은 옛날 코드 그대로다(URL 은 그대로 유지된다).

> 스크립트를 시트에 바인딩하지 않아도 된다 — 첫 요청 때 "포트폴리오 데이터" 스프레드시트를
> 자동으로 만들고 그 ID 를 스크립트 속성에 저장해 계속 같은 시트를 쓴다.

## 2. pc21 연결

`portfolio_sync_config.txt` 를 채운다(이 파일은 `.gitignore` 가 막으므로 커밋되지 않는다):

```
url=https://script.google.com/macros/s/AKfy..../exec
secret=<웹앱의 var SECRET 과 똑같이 — 이미 채워져 있다>
```

확인:

```bash
python portfolio_sync.py --dry
```

- `SECRET 불일치` → 웹앱의 SECRET 과 config 의 secret 이 다르다.
- `응답이 JSON 이 아니다` → 배포 URL 이 틀렸거나(끝이 `/exec` 인지 확인) 액세스가 '모든 사용자'가 아니다.
- `0행 수신` → 아직 아무도 등록하지 않았다(정상).

## 3. 초대제 — 누가 등록할 수 있는지 정한다

기본이 **초대제**다(`REQUIRE_ALLOWLIST = true`). 리서치 메일 수신자만 등록할 수 있고,
목록이 비어 있으면 **아무도 등록하지 못한다**(실수로 전체 공개되는 것보다 낫다).

```bash
python portfolio_allowlist.py --check    # 대상만 확인(전송 안 함, 주소는 마스킹)
python portfolio_allowlist.py --push     # 웹앱에 올린다
```

친구를 새로 넣으려면 `mail_config.txt` 의 `to` 에 추가하고 다시 `--push` 하거나,
목록에 넣지 않고 임시로만 열려면:

```bash
python portfolio_allowlist.py --push --extra friend@example.com
```

★**주소 원문을 구글로 보내지 않는다.** `HMAC-SHA256(SECRET, 주소)` 해시만 올라가고,
웹앱은 입력받은 주소를 같은 방식으로 해시해 대조한다. 시트가 새어도 누가 허용됐는지
알 수 없다. `mail_config.txt` 는 내용을 밖으로 내보내면 안 되는 파일이라 이렇게 했다.

★**SECRET 을 바꾸면 해시가 전부 달라진다** — 그때는 `--push` 를 다시 돌려야 한다.
안 그러면 전원이 등록 불가가 된다.

> 확인 코드를 없애지 않은 이유: 허용목록은 '누가 등록할 수 있나'만 정한다. 수신자들은
> 서로의 주소를 알기 때문에, 코드 확인을 빼면 **남의 주소를 입력해 그 사람 포트폴리오를
> 보거나 고칠 수 있다.** 자격(허용목록)과 본인 확인(코드)은 다른 문제다.

## 4. 친구에게 줄 안내 (그대로 복붙해도 됨)

> 아래 링크에서 본인 이메일과 보유 종목을 등록하면, 매일 아침 그 메일로 보유 현황과
> 전략이 갑니다.
> **링크: (2단계에서 만든 URL)**
>
> - **리서치 메일을 받고 계신 주소로만** 등록됩니다.
> - 이메일을 넣고 **확인 코드 받기** → 메일로 온 6자리 입력 → **확인** 을 누르면 들어갑니다.
> - 들어가면 **엑셀 표처럼** 내 보유가 쭉 뜹니다. `+ 종목 추가` 로 줄을 늘리고,
>   다 넣었으면 **저장**을 누르세요. 고친 줄은 노란색, 새 줄은 초록색으로 표시됩니다.
> - 종목코드는 6자리(앞의 0을 빼먹어도 자동으로 붙습니다)
> - **종목명을 정확히** 적어 주세요. 코드와 실제 이름이 다르면 그 종목은 분석하지 않습니다.
> - **평단가**만 정확하면 됩니다. 매수일시는 받지 않습니다.
> - 물타기·불타기로 평단이 바뀌면 **그 줄의 평단가와 수량을 고치고 저장**하면 됩니다.
> - 지울 때는 그 줄 오른쪽의 `×` 를 누르세요.
> - 이미 등록된 줄의 **증권사·종목코드는 고칠 수 없습니다**. 잘못 넣었으면 지우고 다시 넣으세요.
> - 본인 메일로만 조회·수신됩니다. 남의 포트폴리오는 볼 수 없습니다.
> - **구글 로그인은 필요 없습니다.** "현재 파일을 열 수 없습니다" 가 뜨면
>   **시크릿 창(InPrivate)으로 링크를 다시 열어 주세요.** 구글 계정이 여러 개
>   로그인돼 있으면 생기는 문제이고, 시크릿 창이면 거의 해결됩니다.
> - 투자 판단과 책임은 본인에게 있습니다. 참고 자료입니다.

## 4-1. "현재 파일을 열 수 없습니다" 가 뜰 때

배포한 계정 말고 **다른 구글 계정에서 열면** 이 오류가 흔히 난다.
**권한 문제가 아니다** — 이 웹앱은 구글 로그인 없이도 열리게 배포돼 있다
(쿠키 없는 요청으로 앱 화면이 그대로 내려오는 것을 확인했다).

원인은 브라우저에 **여러 구글 계정이 동시에 로그인**돼 있을 때 구글이 Apps Script
주소를 엉뚱한 계정으로 보내는 것이다. 순서대로 시도하라:

1. **시크릿 창(새 InPrivate 창)에서 링크를 연다.** ← 대부분 이걸로 해결된다.
   이 앱은 구글 로그인이 필요 없으니 시크릿 창에서 아무 문제 없이 쓸 수 있다.
2. 그래도 안 되면 브라우저에서 **구글 계정을 하나만 남기고 로그아웃**한다.
3. 다른 브라우저나 다른 프로필로 연다.

> `/macros/u/0/s/.../exec` 처럼 URL 에 `u/0` 을 끼워 넣는 방법이 돌아다니는데,
> 이 배포에서는 404 가 난다. 쓰지 마라.

**학교·회사 계정(Workspace)** 이라면 관리자가 외부 Apps Script 앱을 막아둔 경우도 있다.
시크릿 창에서도 안 되면 이 경우일 가능성이 크니, 개인 Gmail 로 열어보라고 안내하라.

## 5. 매일 아침 (리서치가 자동으로 한다)

```bash
python portfolio_sync.py            # 웹앱 → portfolios/*.csv
python portfolio_review.py --all    # 사람별 측정
python portfolio_mail.py --all --send
```

## 설계상 지켜지는 것 (바꾸지 마라)

| 규칙 | 어디서 강제되나 |
|---|---|
| **A 의 포트폴리오는 A 에게만** | `portfolio_mail.py` 가 수신자를 `portfolios/<이메일>.csv` **파일명에서** 가져온다. 임의 주소로 보내는 인자가 없다 |
| **본인 등록 = 동의** | 웹앱이 그 주소로 확인 코드를 보내 소유를 확인한다. 남을 대신 등록하는 경로가 없다 |
| **남의 것을 볼 수 없다** | `action=mine` 은 코드 확인 후 자기 행만. 전량 조회(`action=all`)는 SECRET 필요 |
| **선행 0 이 안 죽는다** | 시트 저장 시 `'` 접두 + 읽을 때 양쪽에서 `normTicker_`/`normalize_ticker` |
| **중복 행이 안 쌓인다** | `add` 가 (이메일·종목·증권사) 기준 **덮어쓰기**. 안 그러면 물타기 재등록이 가중평균으로 계산돼 평단·수량이 틀어진다 |
| **동시 접속에도 안 깨진다** | 등록·삭제 전체가 `LockService` 안에서 실행 |
| **화면이 서버를 부를 수 있다** | `google.script.run`. 웹앱 화면은 googleusercontent 샌드박스 iframe 안이라 `fetch` 로 `/exec` 를 부르면 교차출처로 막힌다 |
| **편집 중 코드가 만료돼도 안 잃는다** | 만료되면 로그인 화면으로 돌아가며 **몇 줄이 저장됐는지** 알려준다. 조용히 실패하지 않는다 |
| **확인 코드가 스팸에 안 쓰인다** | 허용목록에 없으면 **메일조차 안 나간다** + 같은 주소 60초 쿨다운 + 하루 60건 상한 |
| **수신자 주소가 구글에 안 남는다** | 허용목록은 HMAC 해시만 저장. `portfolio_allowlist.py` 가 원문을 전송하지도, 로그에 찍지도 않는다 |

## 한계 (알고 있어야 할 것)

- 확인 코드 메일은 **내 Gmail 할당량**을 쓴다(소비자 계정 하루 100통). 상한을 60으로 잡아둔
  이유다. 친구가 늘면 이 숫자를 조정하라.
- 초대제를 끄고 싶으면(아무나 자기 주소로 등록) `.gs` 의 `REQUIRE_ALLOWLIST` 를 false 로
  바꾼다. 권장하지 않는다 — URL 을 아는 사람이 전부 등록할 수 있게 된다.
- 시트에 친구들의 보유 종목이 평문으로 쌓인다. **그 스프레드시트를 공유하지 마라.**
- **자동매매는 카이로스 계좌(내 것)에서만** 돈다. 친구들의 등록분은 KB 든 카이로스든
  전부 **참고용 판단**일 뿐이고, 어떤 주문도 그들 계좌로 나가지 않는다.
