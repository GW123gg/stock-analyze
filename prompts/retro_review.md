## 순서

### 1) 데이터셋 생성
```
python retro_label.py
python retro_forward.py --push
```
- `RETRO\inbox\latest.json`(오늘 날짜) + `roles` 가 가리키는 데이터셋이 생겼는지 확인하고,
  `checksums` 로 무결성을 대조하라.
- ★`retro_label` 출력에 **`무결성=불일치`** 가 보이면 그 사실을 리포트 첫머리에 적어라.
  불일치인데 넘어가면 다음 push 가 검증에서 막힌다.
- ★데이터셋의 `partial_asof_date` 최대값을 **직전 영업일과 대조**해, 다르면
  **지연 거래일 수를 숫자로** 리포트 첫머리에 명시하라.

### 2) 예측 채점
```
cd prediction_scorecard && python gen_scorecard.py
```
(끝나면 다시 WORK 로 돌아와라)

### 3) 분석
`RETRO\inbox\retro_dataset_<날짜>.json` 을 읽고 `회고분석_지시사항.md` §3 질문 순서대로 수행한다.

지켜야 할 규율(원본에 상세히 있다 — 아래는 자주 어기는 것들):
- 수치는 **matured 행만**. §3.9 전체 vs `_src_kind='prediction'` 서브샘플 **병기 의무**.
- `pre_*` = 진입 피처(규칙 사용 OK) / `flow_*_eok`·`dist_disc_count` = **사후 라벨**(진입규칙 금지 = 룩어헤드).
- 새 규칙은 **2~3회 독립 재현**될 때만 승격. 각 발견에 수치 근거 + **반례 1개 이상**.
- ★규칙 총량 계수 단위는 **게이트 패밀리·집행 중 기준**이다(24회차 판정, 상한 30). 현재 총량을 한 줄 갱신하라.
- ★`night_scorecard.md` 를 `market_calls` 와 **합산하지 마라**(같은 거래일 이중계상). 비교 전용이다.
- 억지로 규칙을 만들지 마라. **신규 발행 0건도 정상적인 회차**다.

### 4) 산출
- `RETRO\outbox\회고리포트_<날짜>.md` (§4-(1) 양식)
- `RETRO\outbox\PART_A_추가지시.md` (§4-(2))
- `RETRO\outbox\RETRO_ISSUES.md` 갱신 — 헤더 회차 번호 교체 + 신규 지적 A표 등재 + 미해결 A항목 재점검

### 5) 자체검증 (생략 금지)
§4-(2.5) 6점검을 수행하고 **정정 건수를 보고에 포함**하라(0건이면 "정정 0건"이라고 명시).

### 6) 전파
```
python retro_forward.py --scan-back
```
`WORK\retro_feedback.md` 로 회수된다 — 다음 아침 분석이 `[0.5]` 에서 읽는다.

## 금지
