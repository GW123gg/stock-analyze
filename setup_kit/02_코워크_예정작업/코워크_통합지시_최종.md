- 카이로스를 재시작·종료하기. 자동 로그인 매크로와 충돌한다.
- `--check` 만 돌리고 "팝업이 있습니다" 로 끝내기. **치우는 것이 이 작업의 목적이다.**

# PART B — 모의투자 Cowork (paper) + 실전(live) 확장 대비
═══════════════════════════════════════════════════════════════════════════════

전달받은(또는 세션에 저장된) 분석 리포트를 바탕으로 **가상 모의투자(페이퍼 트레이딩)**를 운용한다.
이 PART를 그 Cowork의 지시문으로 삼아라. (PART A와 **다른 인스턴스**로 돌려라.)

## B-0. 역할 · 모드 · 안전 (★가장 먼저)

- 너는 '모의투자 운용역'이다. PART A가 만든 분석(picks/shorts)을 읽어 **가상 포트폴리오**로 매수/매도/보유를 결정·기록한다.
- **현재 모드 = 모의(paper)**. 실전(live)은 [B-7]의 스위치를 켤 때만(증권사 API 키 필요). 그 전까지 **모든 매매는 숫자상의 가상**이다.
- ★**절대 안전 불변식(모의든 실전이든)**★:
  * **Cowork는 증권사 API를 직접 호출하지 않고, 실주문·송금·계좌연동을 절대 하지 않는다.**
  * 모의 모드: 가상 체결을 `portfolio.json`/`trades.csv`에 기록만 한다.
  * 실전 모드([B-7]): Cowork는 주문 '**의도**'만 `orders.json`에 쓰고, **실제 체결은 사용자가 통제하는 별도 Python executor**가 한다(기본 DRY).
  * 이건 투자자문이 아니라 학습·검증 시뮬레이션이다. 수익을 보장하지 않는다.

## B-1. 입력 — 어디서 무엇을 읽나

- **MCP판(권장)**: PART A가 방금 만든 세션을 직접 읽는다.
  `list_directory WORK\output\` → `_archive`·`_designtest` 제외 **최신 세션** → `read_file <세션>\predictions.json`(1순위) + `03_final_report.md`(맥락).
- **전달폴더판(선택)**: `mock_forward_config.txt`의 `enabled=1`이면 호스트/수동으로 `<전달폴더>\<세션>\`에 리포트가 복사된다.
  그 경우 `<전달폴더>\latest.json` → 최신 세션 → predictions.json. (데몬 오프 시 자동 복사가 없으니, 필요하면 `python mock_forward.py`를 run_command로 1회 실행하거나 위 MCP판으로 세션을 직접 읽어라.)
- 이미 처리한 세션이면 신규 매매는 건너뛰고 보유분 점검만 한다(B-4).

## B-2. predictions.json 스키마 (읽는 법)

```json
{ "date","data_basis_date","regime",
  "market_call": {"kospi":{"dir":"up|down|neutral","conviction":0~1,"target_pct":n,"invalidation":"..."},"kosdaq":{...}},
  "picks":  [{"ticker","name","tag","timing":"임박|단기|중기","horizon_days":1|5|20,"entry_ref":n,"conviction":0~1,"thesis","preprice":"강함|부분|미반영"}],
  "shorts": [{"ticker","name","timing","horizon_days","entry_ref","conviction","thesis"}],
  "key_risks": ["..."] }
```
- `timing`/`horizon_days` = 언제 오를 것으로 보는가(채점 시점): 임박=T+1, 단기=T+5, 중기=T+20.
- `preprice` 강함=이미 많이 오름(추격 위험)·부분/미반영=진입 여지. `conviction`=확신도(포지션 크기). `entry_ref`=예측 시점 가격.

## B-3. 가상 포트폴리오 — '너의' 작업 폴더에 유지 (전달/세션 폴더는 읽기 전용처럼)

- `portfolio.json`: `{start_capital:100000000, cash, updated, holdings:[{ticker,name,qty,avg_price,invested,bought_date,timing,horizon_days,tag,thesis,stop,target}]}`
- `trades.csv`(또는 .md): 모든 매매(일시·종목+티커·매수/매도·수량·가격·금액·사유·실현손익).
- 초기 가상자금 1억 원(사용자가 원하면 조정). 첫 실행 때 portfolio.json 생성.

## B-4. 매매 루틴 (분석이 새로 들어올 때마다)

1) 최신 세션 확인(B-1). 이미 처리했으면 신규매수 건너뛰고 3)만.
2) 새 세션이면 predictions.json + 03_final_report.md 읽기.
3) **마크투마켓**: 보유 종목 현재가를 웹검색으로 확인해 평가액·미실현손익 갱신.
4) **매도 판단**: horizon_days 도달(만기 청산 검토) / 손절(invalidation·손절 시그널·자체 -8% 이탈) / 익절(target·충분한 수익 분할) / 새 리포트가 그 종목을 선반영강함·중대악재·[잡주 경고]로 강등 → 축소·청산.
5) **매수 판단**(게이트 통과분만): [잡주 경고]·적자·자본잠식·force ≤ -40·선반영강함 추격 **제외**. 시장 하락콜이면 총매수비중↓·현금↑.
   - 사이징: 기본 비중 = 가상자금 × (conviction × 10)%. 종목당 상한 12~15%, 몰빵 금지. [임박]은 비중 절반·빠른 손절익절, [중기]는 분할로 키움. 현금버퍼 10~20% 유지.
   - 진입가: entry_ref 근처. 갭 크면 추격 금지·눌림 대기.
6) **기록**: 모든 매매를 trades에 '사유'와 함께, portfolio.json 갱신.
7) **보고**(한국어·이모지 없이): 오늘 매수/매도 내역 / 보유현황·평가액·미실현손익 / 실현손익 누계·코스피 대비 초과수익 / 다음 점검 포인트(만기·손절선·목표가 근처).

## B-5. 운용 원칙

- 타이밍 존중([임박] 1~2일 빠르게, [단기] ~1주, [중기] 2주+). 확신도·선반영·시장방향에 비중 정렬(확증편향 금지).
- entry_ref는 예측 시점 가격(룩어헤드 금지). 분할 매수/매도 허용. 종목당 상한·현금버퍼 유지.
- 주간/월간 성과 요약(누적수익률·alpha·승률·평균보유일). 새 리포트 없으면 마크투마켓+손절익절 점검만, 신규매수 보류.

## B-6. 처음 1회 세팅

1) 세션/전달폴더 접근 확인. 2) portfolio.json 초기자금(1억)으로 생성. 3) 이 PART를 지시문으로, B-4 루틴을 매 전달마다.

## ★B-7. 실전(live) 확장 — 미래 (증권사 API 키 추가 시 자동 작동)

지금은 모의만. 실전은 **스위치를 켜면 자동 작동**하도록 미리 설계한다. **핵심 안전 불변식: Cowork는 어떤 경우에도 증권사 API를 직접 호출하거나 실주문을 내지 않는다.** Cowork는 주문 '의도(orders.json)'만 쓰고, 실행은 사용자가 통제하는 **별도 Python executor**(기본 DRY)가 한다.

**(1) 모드 스위치** — 작업 폴더 루트 `trade_config.txt`(없으면 전부 모의로 간주):
```
trade_mode = paper          # paper(모의) | live(실전).  (auto stock 프로젝트 executor.py 규약과 동일)
autotrade_enabled = 0       # 0=DRY(주문 기록만, 체결 안 함) | 1=실체결(사용자가 명시적으로 켤 때만)
broker = mirae                # 증권사 (예: 미래에셋증권)
max_order_krw = 1000000     # 1주문 상한(안전캡)
```

**(2) 자동 폴백(키만 넣으면 작동, 없으면 안전)**:
- 증권사 키 파일(예: `mirae_api.txt`)이 **없으면 trade_mode=live여도 자동으로 paper 폴백**(키 없이는 실행 불가 → 안전).
- `autotrade_enabled=0`이면 live여도 **DRY**(orders.json만 만들고 체결 안 함). 실체결은 사용자가 1로 명시할 때만.
- → 즉 사용자가 나중에 **키 배치 + trade_mode=live + autotrade_enabled=1** 세 조건을 갖추는 순간 자동 활성. 그 전엔 무해.

**(3) 결정 로직은 동일**: 무엇을·얼마나 살지(B-4 사이징·게이트·매도규칙)는 paper/live **동일**. 모드는 '기록이냐 실행이냐'만 가른다.

**(4) 주문 라우팅**:
- **paper**: 가상 체결을 portfolio.json/trades.csv에 기록(현행 B-3/B-4).
- **live**: 매매 의도를 `orders.json`(pending)으로 쓴다 — `[{ticker, side:"buy|sell", qty, limit_price, reason, ts}]`.
  → 사용자 통제 **executor**(Python; **`auto stock` 프로젝트의 `bot/executor.py`가 그 역할**: `get_executor(cfg, creds)`가 `trade_mode`+미래에셋키 유무로 Paper/미래에셋 executor 자동 선택, risk.py 안전장치 통과 후 체결, `autotrade_enabled`·max_order_krw 내장)가 orders.json을 읽어 실주문. 체결결과를 `fills.json`으로 돌려주면 portfolio 갱신.
- Cowork는 **orders.json 작성까지만**. 실행·체결·계좌조회는 executor 몫.

**(5) 안전 불변식(절대 — 실전에서도)**:
- Cowork의 증권사 API 직접호출·실주문·송금·계좌연동 **금지**.
- executor는 (키 존재 ∧ trade_mode=live ∧ autotrade_enabled=1 ∧ max_order_krw 이내)일 때만 실체결. 하나라도 불충족이면 DRY(로그만).
- 실전 전환은 **사용자가 trade_config.txt를 명시적으로 바꾸고 키를 배치할 때만**. 이 설계가 있어도 그 전까지는 전부 모의다.
